# EduPulse AI — RAG University Knowledge Assistant

A production-style university knowledge assistant that retrieves trusted academic context and optionally uses an LLM to generate grounded answers with source references.

## What is implemented
- RAG retrieval using TF-IDF + cosine similarity
- Overlapping document chunking and Top-K retrieval
- Optional OpenAI grounded generation
- PostgreSQL persistence for users and documents
- JWT authentication with Argon2 password hashing
- Protected document ingestion API
- Persistent knowledge-base reload on application startup
- Responsive browser dashboard with login/register, Q&A, sources and health status
- Docker runtime compatible with cloud `$PORT`
- GitHub Actions CI
- Render Blueprint (`render.yaml`) for web service + managed PostgreSQL

## Architecture
```text
                 Browser
                    |
             FastAPI Web App
             /      |       \
        Auth/JWT   RAG     Health
           |        |
      PostgreSQL  TF-IDF
           |        |
       Documents -> Top-K Context -> Optional OpenAI
                                      |
                              Grounded Answer + Sources
```

## Run locally
```bash
python -m venv .venv
# Windows: .venv\\Scripts\\activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```
Open `http://127.0.0.1:8000/`.

Without `DATABASE_URL`, local development falls back to SQLite. In production, set PostgreSQL through `DATABASE_URL` and use a strong `SECRET_KEY`.

## API
- `POST /api/v1/auth/register` — create account and receive JWT
- `POST /api/v1/auth/login` — authenticate and receive JWT
- `GET /api/v1/auth/me` — inspect current authenticated user
- `POST /api/v1/documents` — protected document ingestion
- `POST /api/v1/ask` — retrieve and answer a question
- `GET /health` — application/database health
- `/docs` — interactive OpenAPI documentation

## Deploy on Render
The repository includes `render.yaml`, which provisions a Python web service and managed PostgreSQL database. Render supports Docker or native Python services and provides a public `onrender.com` URL after deployment. Add `OPENAI_API_KEY` in the service environment if LLM generation is desired.

The included free database configuration is suitable for a demo/portfolio deployment; check the current Render limits before using it for production workloads.

## Security
Never commit API keys or production secrets. `SECRET_KEY` should be generated by the deployment platform, and database credentials should be supplied through environment variables.
